# Witch Pantry Design

## Purpose

Use this skill to keep design work aligned with the current product direction.

Current north star:

- spatial pantry layout and visible machine flow are the lead hook
- desktop-idler support is the secondary differentiator
- customer demand and faction contracts drive goals
- events use soft friction with counterplay
- demo-first and Early Access-friendly delivery

## Use This Workflow

1. Read the current design docs before proposing changes:
   - `Docs/Product-Strategy.md`
   - `Docs/Experience-Pillars.md`
   - `Docs/GDD`
2. Restate the feature or idea in one sentence.
3. Test it against the product direction:
   - does it strengthen spatial pantry play
   - does it improve readability or watchability
   - does it respect cozy tone
   - does it help active play, compact play, or both
4. Decide whether the idea belongs in:
   - prototype
   - demo
   - Early Access
   - 1.0
   - post-launch
5. Prefer cuts, merges, or reframes over adding broad new systems.

## Design Rules

- Prefer one strong fantasy over many decent ones.
- Prefer visible cause and effect over hidden systemic cleverness.
- Prefer room and layout pressure over menu sprawl.
- Prefer controllable demand loops over broad simulated economy claims.
- Prefer soft friction over punishment-first randomness.

## Reject Features That

- create unreadable rooms
- push the game toward spreadsheet-only play
- require too many screens for one production chain
- add hostile friction that breaks the cozy promise
- sound marketable in text but are hard to show in screenshots

## Good Output Shapes

Use this skill when writing:

- design critiques
- feature recommendations
- scope decisions
- roadmap changes
- demo or Early Access positioning

Outputs should end with:

- what changes
- why it helps the product
- what release target it belongs to
