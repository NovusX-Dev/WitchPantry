# Experience Pillars

## Purpose

Use these pillars to judge features, content, UI, rooms, and production priorities.

If a feature does not strengthen at least one pillar, it should be cut, deferred, or reframed.

## Pillar 1: Readable Magical Productivity

The player should understand what the pantry is doing within a few seconds.

Good signs:

- machines visibly imply input, process, and output
- bottlenecks are noticeable without opening deep panels
- upgrades change motion, capacity, layout pressure, or demand response

Bad signs:

- progress only exists as a number going up
- the room looks decorative but not functional
- the player needs labels to understand every object

## Pillar 2: Cozy Optimization

Optimization should feel satisfying, not hostile.

Good friction:

- a contract asks for a potion the pantry can nearly support
- a machine slows down and offers a cheap, readable fix
- a room becomes crowded enough to justify a new space

Bad friction:

- opaque penalties
- destructive loss
- downtime with no counterplay

## Pillar 3: Glanceable Persistence

The game must work as both a normal management game and a compact desktop companion.

Compact mode should show:

- current demand
- gold or main progression currency
- total production health
- worst bottleneck
- one to three useful actions

It should not require room micromanagement or hover archaeology.

## Pillar 4: Marketable Clarity

The game should communicate its value in screenshots, short GIFs, and the first minute of play.

Strong screenshots show:

- one memorable pantry room
- animated production flow
- a visible focal machine
- a clear customer or contract goal
- UI that supports the fantasy instead of burying it

## Decision Checks

- Does it improve screenshot readability?
- Does it deepen pantry optimization?
- Does it respect cozy tone?
- Does it support active and compact play?
- Can a new player understand its value quickly?
- Would this still sound specific if the word "witch" were removed? If not, sharpen the pantry-specific reason.
