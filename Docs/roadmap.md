# Witch's Pantry Roadmap Summary

## Product Direction

The project is now framed around:

- spatial pantry layout and visible machine flow as the lead hook
- desktop-idler support as the secondary differentiator
- customer demand and faction contracts instead of a complex near-term market simulation
- soft-friction events with response and counterplay
- demo-first delivery with an Early Access path

## Phase Structure

### Foundation Prototype

- core runtime model
- first pantry scene
- first machine chain
- basic layout bonuses
- first readable UI shell

### Marketable Demo

- polished starter pantry
- customer demand loop
- compact desktop-idler mode
- save and offline progress
- first event set
- store-ready capture states

### Early Access Core

- more machines and ingredients
- more room growth
- stronger prestige loop
- more factions and visitors
- richer balancing

### 1.0 Expansion

- biome growth
- broader recipe depth
- fuller content breadth
- release polish and launch prep

## Roadmap Rules

- do docs first when a feature changes product identity
- do not introduce systems that weaken readability or cozy tone
- do not treat 3 months as a hard deadline for the full game
- optimize early work for proof of hook, not raw feature count
